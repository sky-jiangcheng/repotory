# GitBuddy 范围收缩与优化执行清单

> 依据 [2026-08-24 产品深度审视](2026-08-24-scope-reduction.md) 拆解。**所有修改遵循「前后端同步」原则**：每个功能域的后端（绑定/DB/service）与前端（组件/路由/locale）在同一阶段完成，两端验证通过才进入下一阶段。
>
> 数据保留原则：砍除功能对应的存量表（`daily_stats`、`project_todos`）**保留但不写入**，不 DROP；代码层全部移除。

## 验证基线

- 后端：`go build ./... && go vet ./... && go test ./...`
- 前端：`cd web && npm install && npm run build`（tsc + vite）`&& npm test`
- 说明：基线时 `web/node_modules` 缺失，`npm run build` 需先 `npm install`。
