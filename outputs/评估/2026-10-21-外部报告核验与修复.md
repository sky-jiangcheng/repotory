## 二、P0 证伪：测试门禁本来就是绿的

报告称 `internal/search/hybrid`、`internal/search/vectordb`、`internal/service` 三个包
共 34 条测试因沙箱 loopback 不通而失败，并援引 `ai_stream_test.go` 的注释作为
「httptest 在沙箱不可用」的先例。

**实测（本机与 CI 同一命令）**：

```bash
go test -race -timeout 10m ./...    # CI 的 go-test job 用的就是这条
```

结果：**36 包全绿，52s，零 FAIL**。其中报告点名的三个包分别
`hybrid 3.961s` / `vectordb 4.231s` / `service 34.645s`，全部 ok。

三重反证：

1. **CI 上一次运行的 `Run Go tests` step结论是 `success`**（run `39561813064`），
   GitHub 托管 runner 有正常 loopback。
2. 报告描述的失败模式是「环境性」，但仓库里的 httptest 测试全部通过——
   说明报告作者所处沙箱的 loopback 限制**不适用于**本项目常规开发与 CI 环境。
3. 报告建议的修复动作（把 8 个测试文件改成 fake struct / 移入 `_live_test.go`，
   预估 2-3 天）若实施，反而会**降低覆盖率**——现在这些测试真实走 HTTP 路径，
   改成 fake 后 embedder 的错误处理、重排逻辑、round-trip 语义都不再被验证。

**顺带修正一处认知**：`ai_stream_test.go` 的注释说「httptest loopback 在沙箱不可用，
故 SSE 解析做成纯函数」——这条注释描述的是**当时那个沙箱**的限制，被后续读者
当成普遍事实引用了。项目实际可以在有 loopback 的环境里正常跑 httptest。

**结论：P0 是评估环境的局限，不是项目缺陷。按报告建议动这批测试会是净损失。**
