01任务与约束

现有图标是 RepoNest 时期的直译：一张仓库卡片被两道弧线托住，形似巢碗。品牌名两代之前已改为 Repotory，但图形语义仍停在“巢”；配色为深海军蓝 + 金，与界面主色 #2563EB 不一致；16px 下卡片与双弧线互相挤压，缩略图糊成一团。

约束要求
语义以 R 为字标，去掉“巢”的直译；可承载“仓库 / 提交节点”但不靠贴上去的圆点
尺寸512 画布；16 / 32 / 64 / 128 / 512 五档都要成立
色彩与 UI 主色同源；单色（VS Code 主题着色）可用
形制几何构造、平切端点、可在 200% 放大下逐点检查

02参考研究

IBM（Paul Rand, 1972）

IBM 字标由 8 条等距横纹构成。它不靠装饰，而靠一套可复用的模块系统：所有字母共享同一笔画宽度与端点规则，缩小后仍是同一节奏。可迁移的部分是“统一笔画 + 平切端点 + 单色可读”，而不是条纹本身（条纹在 16px 会糊）。

X（2010s 品牌更新）

X 是单一形状、锐角、极高对比：没有渐变、没有第二层装饰，缩到 16px 仍是一个可辨的轮廓。可迁移的是“一个可记忆的细节 + 轮廓优先”。

结论：字标需要系统（网格、统一笔画、平切）与一个细节（IBM 的条纹、X 的锐角）。Repotory 选用：45° 顶部斜切 + 碗腿衔接圆角 + 腿自上而下收分。

03探索 A：描边拼字（淘汰）

问题：描边拼出来的仍是“字体的骨架”，端点靠 stroke-linecap 模拟，无法控制收分与衔接；16px 下笔画与内白互相粘连。整轮淘汰。

04探索 B：填充轮廓

关键改动：不再用描边，改为一条闭合轮廓。这带来三个可控点——笔画宽度、内白形状、腿的收分，都能精确到像素。T1（圆角内白）/ T2（圆形内白）/ T3（硬角）中，圆形内白在 16px 退化成一个点，语义偏移，淘汰。

05细化：比例与衔接

  • 保留腿自上而下收分 72 → 58：避免右下角发沉，视线沿腿落到基线。
  • 保留碗—腿 42 圆角：去掉两段直线相交的生硬三角尖。
  • 保留顶部 45° 斜切 24：整枚图标唯一的“手工记号”，对应 X 的锐角记忆点。
  • 淘汰青色节点圆点：像贴上去的徽章，且与字标笔画抢注意力。

06最终候选

推荐 F2：斜切 24 在 512 下清楚、在 128 下仍成立、在 32/16 下自然消失，不影响辨识。F4 的硬内白更“工程感”，但小尺寸下内白容易过小。

08应用测试

16px 下保留字干、内白与腿的收分；圆角与斜切在该尺寸自然消失，不产生噪点。单色版本可直接用 currentColor 交给 VS Code 主题着色。
