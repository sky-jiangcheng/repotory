## 二、发现并修复的缺陷

### 缺陷 1（唯一真缺陷）：DiffViewer 上下文行全部挤成一行

**现象**：笔记版本历史点「Diff」，面板里整个 diff 渲染成**一整行连续文本**，例如：

```
# E2E 巡检 v2 这条笔记由 2026-10-24 自动化巡检创建。 - 验证点 1 - 验证点 2 - 验证点 3（新增） ```go fmt.Println("hello v2") ```
```

有增删时反而"看起来正常"，因为增删行各自成行；一旦 diff 以上下文行为主（最常见的情况：只改了一两行），整个面板就不可读。

**根因**：`web/src/components/DiffViewer.tsx` 用 `text.split('\n')` 拆行后，每行渲染一个 `<code>`：

```tsx
<pre className={s.diffPre}>
  {lines.map((line, i) => { ... return <code key={i}>{line}</code> })}
</pre>
```

- `<pre>` 上的 `white-space: pre` 只能保留**文本节点内部**的换行，而 JSX 生成的相邻 `<code>` 之间**没有任何文本节点**（换行符被 JSX 编译器吞掉）；
- `<code>` 默认 `display: inline`，所以相邻行盒直接首尾相连；
- 原 CSS 只给 `.diffLineAdd` / `.diffLineDel` 加了 `display: block` → **只有 +/- 行能分行**，上下文行全部塌成一行。

**后端无责**：`internal/diff/diff.go` 的 `diff.Lines` 输出是正确的逐行 unified diff（` `/`+`/`-` 前缀），已用真实 RPC 响应核对：

```
' # E2E 巡检 v2\n \n 这条笔记由...\n \n - 验证点 1\n - 验证点 2\n - 验证点 3（新增）\n \n ```go\n fmt.Println("hello v2")\n ```'
```

**修复**：`web/src/components/DiffViewer.module.css` 把 `display: block` 上提到共享的 `.diffPre code` 规则，增删变体只负责着色：

```css
.diffPre code {
  font-family: inherit;
  display: block;   /* 每行独占一行 */
}
.diffLineAdd { background: var(--success-soft); color: var(--success); }
.diffLineDel { background: var(--danger-soft); color: var(--danger); }
```

**影响面**：该组件被笔记版本面板（`VersionHistoryPanel`）与 Review 页 wiki 页面历史（`Review.tsx:691`）**共用**，一处修复两处受益。

**回归验证**：
- 修复后（`31-diff-fixed.png`）：11 行各自成行；
- 造真实增删场景（`32-diff-with-changes.png`）：`+# E2E 巡检 v3` / `-# E2E 巡检 v2` / `+- 验证点 4（改过）` / `-- 验证点 2` / `+fmt.Println("hello v3")` / `-fmt.Println("hello v2")` 全部绿底/红底正确着色并逐行对齐。

**新增守卫**：`web/src/components/DiffViewer.test.tsx`（3 用例）
1. 每个 diff 行渲染为独立 `<code>` 元素；
2. `+`/`-` 行带各自 class；
3. 通过 `node:fs` 读样式表断言 `.diffPre code` 含 `display: block`（vitest 不求值 CSS module，DOM 断言看不见这条规则，故按 `styles/semanticInk.test.ts` 的既有手法直接读 CSS）。

## 三、非缺陷说明（记录，不改代码）

### 1. AI 问答返回上游限流错误

首页「Knowledge Base Assistant」提问后返回：

```
AI request failed: Upstream error from Nvidia: ResourceExhausted: Worker local total request limit reached (16/16)
```

这是**上游推理服务（NVIDIA）的并发配额耗尽**，不是前端或后端缺陷：错误被正确捕获、以可读文案展示、并提供「Copy Reply / Save as Note」降级入口。应用侧行为符合预期，无需改动。

### 2. Review 页存在历史遗留 Failed 任务

后台任务列表首条为 `Failed | compile BookStore | 2/8 notes done | Error: interrupted by application restart; work is not resumed because the stopping point is unknown`。属此前重启中断的历史记录，非本次巡检产生；文案本身已把原因说清。

### 3. Quick Note 为两步式（先选项目 → 再编辑）

点「Quick Note」先弹项目选择面板（列出 37 个项目），选一个才进编辑器。这是有意设计（笔记必须挂靠项目），不是交互缺陷。项目清单里没有名为 `repotory` 的项目（`Script` 是其父项目），符合实际目录结构。

### 4. 巡检环境的两个非应用问题

- **Chromium 起不来**：`Target crashed` / `sandbox initialization failed`。本机沙箱环境不允许 Chromium 自带的 user-namespace sandbox，需在 `.playwright/cli.config.json` 里加 `--no-sandbox --disable-dev-shm-usage --disable-gpu`（本次已加，并加入 `.gitignore`）。
- **后台进程被回收**：`nohup ... &` 起的 Vite / API 会在 Bash 调用结束时被沙箱回收，必须用 `run_in_background: true` 的常驻任务方式启动。
