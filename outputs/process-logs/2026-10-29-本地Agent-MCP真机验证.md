# 本地 Agent + MCP 真机验证（2026-10-29）

对应 TODO 4.2「『本地 Agent 的默认记忆层』落成可复现的配方」。产物是手册页 [docs/features/local-agent-recipe.md](../../docs/features/local-agent-recipe.md)（+ 英文镜像）；本文件是那次实测的原始记录。

## 要证的是什么

TODO 的原话是「技术上成立，但没人验过」。所以要证的不是设计，而是四件具体的事：

1. 一个**完全离线**的模型能拿到 `repotory-mcp` 的 18 个工具；
2. 它能调用 `repotory_handoff` 把结论落库；
3. **另一个进程**（不共享对话历史）能通过 `repotory_context` 读到上一条，并回答出只有那次会话才知道的事实；
4. 这条链路**没有一条出网请求**。

第 3 点是「记忆层」这个词唯一有分量的地方——前面两点只能说明「工具通了」。

## 隔离纪律（活库零接触）

`platform.GetDbPath()` = `os.UserConfigDir()/repotory/repotory.db`，`platform.DefaultScanRoots()` 在 darwin/linux 上就是 `os.UserHomeDir()`。所以把 `HOME` 指到 `/tmp` 下，**库和默认扫描根同时被隔离**，不需要任何测试专用的开关。

活库 sha256 前后一致：

```text
$ shasum -a 256 "$HOME/Library/Application Support/repotory/repotory.db"
09f3bc4960a66fb3f98e392d52304fef063ade58ec6359422615649ffcb93d2b
```

（会话开始前、两轮会话结束后各取一次，相同。）

演示仓库放在 `$HOME/demo-repo`（一个提交：`feat: scaffold ledger service with health endpoint`）。注意 `internal/grouper` 的项目分组根是仓库的**父目录**，所以它被识别成项目 `home`，`repotory_context` 返回的标题也是 `# Project Context: home`——这是既有行为，不是本次验证的缺陷。

冷启动用 `repotory_scan` 播种并同步扫描，得到 1 仓库 / 1 项目，`success: true`。

## 会话 1：模型自己发出 handoff

一次进程调用 = 一次会话。`local_agent.py` 连上 MCP、把 `tools/list` 的结果原样转成 OpenAI `tools` 数组，然后交给本地模型。

提示词（`p1.txt`）：

```text
Call the tool repotory_handoff exactly once with these arguments and then stop:
project_id = 2
agent = "local-ollama-qwen2.5-3b"
summary = "Read the ledger-core README and confirmed the /health endpoint contract."
changes = ["no file changes; read-only review"]
gotchas = ["the /health endpoint returns 200 even when the account balance is negative"]
next_steps = ["add a balance regression test before wiring /health into CI"]
Do not call any other tool.
```

输出（`session1.txt` 全文）：

```text
MCP tools available to the model: 18

--- tool call: repotory_handoff ---
{"next_steps": ["add a balance regression test before wiring /health into CI"], "project_id": 2, "agent": "local-ollama-qwen2.5-3b", "summary": "Read the ledger-core README and confirmed the /health endpoint contract.", "changes": ["no file changes; read-only review"], "gotchas": ["the /health endpoint returns 200 even when the account balance is negative"]}
--- tool result (first 1200 chars) ---
{
  "note_id": 1,
  "title": "Session Handoff 2026-10-29 09:19",
  "tags": "handoff"
}
```

工具是模型自己选的（`tool_choice: auto`），脚本只负责转发。

## 会话 2：另一个进程读回来

新进程、新 MCP 连接、不带会话 1 的任何消息。提示词（`p2.txt`）：

```text
Call the tool repotory_context exactly once with path = "/tmp/repotory-verify/home/demo-repo".
Then read the context it returns and answer this question in one sentence: what gotcha did the PREVIOUS session record?
Do not call any other tool.
```

输出（`session2.txt` 全文；上下文中间略去 Readme/语言统计段落不影响判断）：

```text
MCP tools available to the model: 18

--- tool call: repotory_context ---
{"path": "/tmp/repotory-verify/home/demo-repo"}
--- tool result (first 1200 chars) ---
# Project Context: home

- Root path: `/private/tmp/repotory-verify/home`
- Knowledge notes: 1 | Open todos: 0

### Session Handoff 2026-10-29 09:19

- Tags: handoff | Updated: 2026-10-29T01:19:25Z

> Written by `local-ollama-qwen2.5-3b`

Read the ledger-core README and confirmed the /health endpoint contract.
```

这就是「跨会话记忆」的最小闭环：模型本身没有任何持久状态，第二条会话里的每个字都来自 SQLite 里那条 handoff。

## 抓包：确认没有出网

在 ollama 前面挂了一个 loopback 记录代理（`proxy.py`，监听 `11435`，转发到 `11434`，把每个请求的 `path` / `model` / `tool_count` / `tool_names` / `message_roles` 记进 JSONL）。重跑会话 2，`proxy.jsonl` 记了两条：

```json
{"path": "/v1/chat/completions", "model": "qwen2.5:3b", "stream": false, "tool_names": ["repotory_agent_score", "repotory_ai_audit", "repotory_ai_review_rules", "repotory_ask", "repotory_context", "repotory_handoff", "repotory_integrity", "repotory_notes_create", "repotory_notes_list", "repotory_notes_organize", "repotory_notes_read", "repotory_notes_search", "repotory_notes_update", "repotory_projects_list", "repotory_projects_stats", "repotory_scan", "repotory_wiki_read", "repotory_wiki_search"], "tool_count": 18, "message_roles": ["system", "user"], "user_content": []}
```

第二条除 `message_roles` 变成 `["system", "user", "assistant", "tool"]` 外与上一条完全相同——同 18 个工具、同 `path`、同 `model`。

第一条是模型决定调用工具，第二条带着 `tool` 结果回来。两次都只打到 `127.0.0.1`，请求体里是 18 个 repotory 工具。

## opencode v2.0.29：连上了，但不把工具交给模型

这是这次验证里花时间最多的一段，也是唯一失败的一段。现象：

- 日志：`mcp connected server=repotory tools=18`（`directory=/private/tmp/repotory-verify/home/demo-repo`）；
- 但发给模型的请求里只有 opencode 自带的 12 个工具。用 LM Studio 的 27B 复现时抓到的原文（`proxy-lms.jsonl`）：

```json
{"path": "/v1/chat/completions", "model": "prism-ml/bonsai-27b", "stream": true, "tool_names": ["edit", "glob", "grep", "question", "read", "shell", "skill", "subagent", "webfetch", "websearch", "write", "execute"], "tool_count": 12, "message_roles": ["system", "user"], "user_content": []}
```

`repotory_*` 一个都没有。排除矩阵（每一格都实测过）：

| 变量 | 取值 | 结果 |
|---|---|---|
| 模型 | ollama `qwen2.5:3b` / `qwen2.5-coder:7b`；LM Studio `prism-ml/bonsai-27b`（27B） | 都是 12 个内置工具 |
| 配置形状 | `mcp.servers.{...}` / `mcp.{name}`；项目级 `./opencode.json` / `--global` | 都 `mcp connected`，都进不去 |
| 显式开关 | `"tools": {"repotory_*": true}`、`"tool_call": true`、`"npm": "@ai-sdk/openai-compatible"` | 无效 |
| 换 MCP server | 另写一个只有 1 个工具的对照 server（`mini_echo`） | 同样 `mcp connected server=mini tools=1`，同样进不去 |

对照 server 也失败这一点是关键：**问题不在 repotory 的工具 schema，而在客户端把 MCP 工具并入模型 tool schema 的那一步**。opencode 文档对「工具调用不工作」只有一条提示（把 ollama 的 `num_ctx` 调到 16k–32k），本机调到 32k 也不生效。

### 顺带踩到的坑（不是 opencode 的）

- ollama 的 OpenAI 兼容端点在 `/v1` 下，`baseURL` 写成 `http://127.0.0.1:11434` 会得到 `404 page not found`。
- 用户本机有一个常驻 opencode 后台服务占着默认端口 `49374`；隔离验证里用 `--standalone` 跑 `run`/`models`，其它子命令 `opencode service set port 49375`。
- 3B 模型对多步提示词会跑偏：一次三步提示下它先按 handoff 的参数调了 `read`，再往 `https://github.com/...` 写文件（在演示仓库里留下了一个名为 `https:` 的目录），然后 `webfetch` 404。这是模型能力问题，不是接线问题——改成单目的提示词后就稳定了。

## 记录用的最小驱动

`local_agent.py` 全文（约 170 行）。它不是产品，只是把「客户端本该做的事」显式写出来：

```python
#!/usr/bin/env python3
"""Minimal MCP-driving local agent used to record the 4.2 verification.

Two ingredients, nothing else:
  1. repotory-mcp over stdio (the same binary every real client spawns), and
  2. an OpenAI-compatible local model endpoint (ollama / LM Studio on loopback).

It is a RECORDING HARNESS, not a product. It exists because the client under
test (opencode v2.0.29) connects the MCP server but never puts the MCP tools
into the model's tool schema, so the loop cannot be driven from there.

Each invocation is one "session": a fresh process, a fresh MCP connection, no
carried-over conversation. That is what makes the second run a real
cross-session test rather than a continuation.

Usage:
  python3 local_agent.py --prompt-file p1.txt [--max-turns 4]
"""
import argparse
import json
import os
import subprocess
import sys
import urllib.request

MCP_BIN = os.environ.get("REPOTORY_MCP_BIN", "/tmp/repotory-verify/repotory-mcp")
BASE_URL = os.environ.get("LOCAL_BASE_URL", "http://127.0.0.1:11434/v1")
MODEL = os.environ.get("LOCAL_MODEL", "qwen2.5:3b")


class MCP:
    """Just enough MCP: initialize, tools/list, tools/call, over stdio."""

    def __init__(self, binary):
        self.proc = subprocess.Popen(
            [binary], stdin=subprocess.PIPE, stdout=subprocess.PIPE,
            stderr=subprocess.PIPE, text=True,
        )
        self.next_id = 1
        self._request("initialize", {
            "protocolVersion": "2024-11-05",
            "capabilities": {},
            "clientInfo": {"name": "local-agent-driver", "version": "0.1"},
        })
        self._notify("notifications/initialized")

    def _send(self, msg):
        self.proc.stdin.write(json.dumps(msg) + "\n")
        self.proc.stdin.flush()

    def _notify(self, method, params=None):
        msg = {"jsonrpc": "2.0", "method": method}
        if params is not None:
            msg["params"] = params
        self._send(msg)

    def _request(self, method, params=None):
        mid = self.next_id
        self.next_id += 1
        msg = {"jsonrpc": "2.0", "id": mid, "method": method}
        if params is not None:
            msg["params"] = params
        self._send(msg)
        while True:
            line = self.proc.stdout.readline()
            if not line:
                raise RuntimeError("MCP server closed the pipe (stderr: %s)"
                                   % self.proc.stderr.read()[:500])
            resp = json.loads(line)
            if resp.get("id") == mid:
                if "error" in resp:
                    raise RuntimeError("MCP error: %s" % resp["error"])
                return resp["result"]

    def tools(self):
        return self._request("tools/list").get("tools", [])

    def call(self, name, args):
        res = self._request("tools/call", {"name": name, "arguments": args})
        out = []
        for block in res.get("content", []):
            if block.get("type") == "text":
                out.append(block.get("text", ""))
        return "\n".join(out)

    def close(self):
        try:
            self.proc.terminate()
            self.proc.wait(timeout=5)
        except Exception:
            self.proc.kill()


def to_openai_tools(mcp_tools):
    return [
        {
            "type": "function",
            "function": {
                "name": t["name"],
                "description": t.get("description", ""),
                "parameters": t.get("inputSchema", {"type": "object", "properties": {}}),
            },
        }
        for t in mcp_tools
    ]


def chat(messages, tools):
    body = json.dumps({
        "model": MODEL,
        "messages": messages,
        "tools": tools,
        "tool_choice": "auto",
        "temperature": 0,
        "stream": False,
    }).encode()
    req = urllib.request.Request(
        BASE_URL + "/chat/completions", data=body, method="POST",
        headers={"Content-Type": "application/json"},
    )
    with urllib.request.urlopen(req, timeout=300) as resp:
        return json.loads(resp.read())


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--prompt-file", required=True)
    ap.add_argument("--max-turns", type=int, default=4)
    ap.add_argument("--system", default=(
        "You are a coding agent with tools. Use the tools you are given. "
        "When the user asks you to call a specific tool, call it with the "
        "given arguments and nothing else."
    ))
    args = ap.parse_args()

    prompt = open(args.prompt_file).read().strip()
    mcp = MCP(MCP_BIN)
    tools = to_openai_tools(mcp.tools())
    print("MCP tools available to the model: %d" % len(tools), flush=True)

    messages = [{"role": "system", "content": args.system},
                {"role": "user", "content": prompt}]
    for turn in range(args.max_turns):
        resp = chat(messages, tools)
        msg = resp["choices"][0]["message"]
        calls = msg.get("tool_calls") or []
        messages.append({"role": "assistant", "content": msg.get("content") or "",
                         **({"tool_calls": calls} if calls else {})})
        if not calls:
            print("\n--- assistant ---\n%s" % (msg.get("content") or ""), flush=True)
            break
        for call in calls:
            name = call["function"]["name"]
            raw = call["function"].get("arguments") or "{}"
            try:
                call_args = json.loads(raw)
            except json.JSONDecodeError:
                call_args = {}
            print("\n--- tool call: %s ---\n%s" % (name, json.dumps(call_args, ensure_ascii=False)), flush=True)
            try:
                result = mcp.call(name, call_args)
            except Exception as e:  # surface the failure to the model, like a real client
                result = "error: %s" % e
            print("--- tool result (first 1200 chars) ---\n%s" % result[:1200], flush=True)
            messages.append({"role": "tool", "tool_call_id": call.get("id", ""),
                             "content": result[:20000]})
    mcp.close()


if __name__ == "__main__":
    main()
```

它做三件事：`initialize` + `tools/list` 拿 schema（`MCP.tools`）→ 转成 OpenAI `tools`（`to_openai_tools`）→ 把模型的 `tool_calls` 映射回 `tools/call`（`MCP.call`）。没有任何 repotory 私有知识；换任何 stdio MCP server 都能跑。

## 结论与边界

- 链路成立：离线模型 + 本地库 + MCP，跨会话命中 handoff，全程 loopback。
- 用 `qwen2.5:3b` 跑通只说明接线对，**不说明小模型可靠**；配方里写的是「真实使用建议 7B 以上」。
- opencode 2.0.29 的问题记成**已知限制**并写进手册，不当成通过项；客户端修好后这页的限制段应删掉。
- 未验证：Claude Code / Cursor 的实际接入（本机没有这些客户端）。手册里的命令来自各自文档，本次没有真机跑过——这一点在手册里不宣称已验证。
